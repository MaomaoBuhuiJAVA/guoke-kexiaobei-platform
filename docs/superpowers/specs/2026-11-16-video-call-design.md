# 科小贝视频通话方案草案

日期：2026-11-16

状态：用户已确认选择 A：实时音视频通话。实现与配置说明见 robot-console/docs/realtime-video-call.md；真实百炼服务待配置与验收。

## 目标体验

用户在科小贝对话中点击“视频通话”，授权摄像头和麦克风后，可以把物品、绘本或实验现象展示给科小贝，直接用语音提问。科小贝结合当前画面和对话上下文回答，并同步显示字幕。用户可以继续追问或在回答过程中插话。

例如：把一片叶子放到镜头前问“这是什么？”，再指着叶子问“为什么这里变黄了？”。回答应区分画面中确实可见的特征与需要进一步确认的原因；画面不清楚时，请用户靠近或调整角度。

## 两种实施路径

| 路径 | 首版行为 | 取舍 |
| --- | --- | --- |
| A：实时音视频，推荐 | 持续输入音频和画面，模型直接输出语音及字幕；支持语音插话 | 更接近豆包视频电话，需要验证实时模型权限、音色、费用与浏览器兼容性 |
| B：复用现有逐轮通话 | 每次提问携带最新摄像头截图，复用现有识别和语音合成 | 接入改动较少，但存在逐轮等待，连续动作理解和语音打断体验有限 |

建议采用 A。现有千问图片能力可用于 B，或作为实时服务不可用时的后续替代能力。首版不同时建设两套完整视频通话链路。

## 推荐架构

优先采用百炼 Qwen-Omni-Realtime 的 WebRTC 接入方式。浏览器采集音频与视频；业务后端完成鉴权、会话创建与 SDP 信令代理，长期 API Key 始终留在服务端。媒体轨道连接实时模型，DataChannel 承载会话事件、字幕和控制消息。

模型名称、地域和业务空间通过服务端配置管理，实施前以账号实际可用版本为准。当前官方文档列出实时视频、WebRTC 视频轨道、VAD 和工具调用能力；已有普通千问密钥不等于已经验证实时模型权限。

实时视频问答由实时模型处理，需要科学诗、故事或实验等园本资源时，通过受控工具调用现有资源检索。工具执行和资源权限由业务后端校验，不允许浏览器提交任意工具执行。

把媒体采集、实时连接、播放及打断、通话界面拆成独立模块，`SciencePet.tsx` 负责入口和聊天记录衔接，避免继续集中新增通话逻辑。

## 通话界面与行为

- 在现有对话标题栏增加视频通话入口。
- 通话画面以摄像头预览为主，保留科小贝形象、连接状态和最近一轮字幕。
- 提供切换前后摄像头、开关摄像头、麦克风静音、扬声器开关和挂断。
- 关闭摄像头后立即停止视频轨道，并取消模型对当前画面的访问；重新开启需重新确认画面已就绪。
- 支持用户语音打断，清除尚未播放的旧回答；保留按钮打断作为补充入口。
- 画面更换后使用更新的画面回答，不能把旧画面描述为当前所见。
- 挂断、退出页面或页面进入后台时结束会话，停止媒体轨道和播放，丢弃迟到事件。

## 异常与数据处理

- 摄像头拒绝授权、设备被占用、无摄像头、麦克风不可用时显示对应提示，允许返回普通对话。
- 网络断开时显示连接状态；重新连接必须建立新会话，禁止恢复旧音频播放。
- 应用侧默认不持久化原始摄像头画面或录音；如接入聊天文字记录，遵循现有用户数据隔离方式。供应商数据处理策略需按实际服务配置核对。
- 回复沿用面向幼儿的简短、准确风格；看不清就说明不确定，不仅凭画面推断具体身份、健康状况或危险材料的安全性。

## 验收标准

1. 用户可以完成授权、预览、连接和一次基于真实物品画面的语音问答。
2. 替换镜头前物品后，追问“现在呢”，回答反映新画面。
3. 回答过程中插话可停止旧播放，并围绕新问题回答。
4. 切换摄像头、关闭摄像头、静音和挂断实际影响对应媒体轨道。
5. 拒绝授权、断网、后台切换和连续重连不会留下采集、播放或旧会话回复。
6. 核对桌面 Chrome、Android Chrome 和 iOS Safari；微信内浏览器单独实机验证，按实际支持情况显示可用入口。
7. 测量从用户说完到首段语音播放的延迟，并记录网络、设备和模型版本；目前不承诺未经实测的延迟数字。
8. 修改相关模块后运行针对性的生命周期与接口测试、类型检查及构建校验；上线时完成真实浏览器交互和静态资源验收。
