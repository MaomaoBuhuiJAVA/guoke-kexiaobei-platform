# 故事完整性二次修复

## 复现与原因

用户截图中的“请你生成一个跟火焰有关的科学故事”在正式站被返回为安全替代活动，“给我讲一个科学故事”仅约221字。语音仍存在brief路径72字和content路径2400字硬裁剪，截图中的半句话加省略号符合旧裁剪行为；上一轮仅验证了显式故事请求和固定文本，未覆盖这组主题请求。

- 火焰安全分支只按主题判断，没有区分叙事与实际实验操作，直接覆盖故事正文。
- 普通文字故事提示词默认200至350字；语音模式仍按关键词设置硬上限，误分类时可能截断完整模型回答。
- 不带“讲/听”动词的主题式故事请求没有稳定采用相同叙事路径。

## 修复

- 文字与语音故事默认约500至800字，包含场景、角色、疑问、两至三个推进情节、发现和完整结尾。用户明确指定短故事或篇幅时优先遵从。
- 取消显示文本和语音队列的72/2400字符硬裁剪，不再在句中插入省略号；普通知识问答由提示词保持简洁，模型仍有生成token预算。
- 火焰主题故事按叙事交付，不替换成实验材料、活动步骤或安全告示。明确找/查/推荐故事继续查真实资源；实际危险实验操作继续原有安全处理。
- 故事统一优先文字模型；语音内容预算3000 tokens，保留流式分段合成与顺序播放。补充火焰科学解释约束，避免把拟人语言、颜色排序等当成科学原因。

## 验证

- 新回归先复现失败，再通过：截图三条原句、完整长文本不被裁剪、播报跨越旧72字边界、找/查/推荐故事继续知识库检索，既有危险操作保护测试继续通过。
- 本地真实模型与浏览器（390×844，Edge/Playwright）：两条文字请求返回594字和473字，语音“火焰有关的科学故事”739字、“再讲一个”724字；分别27、26次真实TTS 200，WAV以8倍速实际播放以缩短验收时间。逐字符核对模型最终回复、界面正文与全部TTS文本一致，包括结尾；无页面脚本错误。
- 浏览器输入通过模拟识别事件提供，真实手机麦克风授权和人工听感不在此项自动化验证范围内。
