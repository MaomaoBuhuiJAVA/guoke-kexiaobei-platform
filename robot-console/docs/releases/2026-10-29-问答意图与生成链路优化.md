# 2026-10-29 问答意图与生成链路优化

## 用户反馈与原因

“我想听一个科学故事”返回“资料库暂未收录”，没有实际讲故事。路由把“科学故事”关键词直接判作目录检索；未命中后，短请求被固定回复提前结束，修改大模型提示词本身不能修复此路径。

## 修改

- 先识别讲述、原创、原理解释、活动设计等意图，再判断是否属于真实资源检索。指定标题、库内原文、视频和步骤图等查询继续保留严格的真实资料约束。
- 普通问答与原创故事不再无条件检索目录，也不向模型注入与问题无关的“未命中”文本；不再把无关资源作为回答来源。
- 故事与原创诗明确标注原创，默认给出适龄内容；保持科学因果准确，不编造园本来源或链接。追问“短一点”等承接上一轮主题与文稿。
- 缺少实验名称与现象时先简短确认，不臆测无关故障；明确要完整教案才展开完整结构。去掉旧 Dify 教案提示词对资源命中及不能识图的过时要求。
- 普通聊天关闭长推理，复杂文档保留原配置。电话故事使用文本模型，但保留语音的短 token 预算、12 秒超时和最终 72 字限制；普通电话问答仍走原快模型。
- 未指定主题的故事使用明确的日常科学主题，补充光反射与影子、蒸发与物质消失等易混淆因果的复核。简单活动走直接回答模式，完整教案与文档继续保留推理。

## 验证方式

- `conversation-quality.test.ts` 覆盖截图请求、原创诗、原理解释、简单活动、指定条目和多轮修改；新增测试在修复前复现了固定回复与上下文丢失问题。
- `model.test.ts` 验证直接回答模式及电话故事的模型选择、预算和推理配置。
- `scripts/conversation-quality.live.test.ts` 仅在 `RUN_LIVE_CHAT_QA=1` 时调用真实模型，正常 CI 跳过；覆盖普通故事、风/影子故事、原创诗、知识问题、含糊问题、活动设计、命中/未命中资源、电话问答和追问。真实回答保存到仓库外，不提交凭据。
- 本地迭代发现并修复了长推理等待、无关故障猜测、旧教案检索前提及电话故事的错误拟人解释。实测耗时只是当时的样本，不保证未来服务时延。
- 上线只使用 GitHub Actions 的 Linux 构建包，ECS 不安装依赖或构建；数据库、模型密钥和业务数据不变。
