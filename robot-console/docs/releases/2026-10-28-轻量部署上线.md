## 失败候选处理

早先的 `/opt/guoke/releases/20261028-voice-ai-fix-r1` 是 Windows 构建产物，Prisma 符号链接指向开发机路径，启动首页和资源库时报 `Cannot find module '@prisma/client-2c3a283f134fdcb6`。随后生成的第一版 Linux 包目录布局不符合 ECS systemd 约定，切换后曾出现短暂 502，已回滚并删除。这次故障说明隔离启动验收还必须覆盖 systemd 实际入口与沙箱目录。两者均未作为最终线上版本保留。

## 静态资源显示故障修正

- 用户截图发现页面无样式且图片损坏；实测 HTML 为 200，但 `/_next/static/` 下 CSS、JS 返回 404。原验收只看页面状态码，不足以验证实际显示。
- 根因：发布包只在 release 根目录放置 `.next/static` 和 `public`，没有完整复制到实际运行的 `.next/standalone` 中；Next.js 从 `server.js` 所在目录读取资源。
- 修复：将当前包内原始资源完整复制至 `.next/standalone/.next/static` 与 `.next/standalone/public`，重启应用刷新文件清单。未修改业务代码、数据库或凭据，也没有在 ECS 构建。
- 复测：原先返回 404 的 CSS、JS、标志 PNG 和首页 WebP 均返回 200，响应类型正确；首页、资源库、科学乐园正常返回 200。
- 防复发：修正 Linux 构建工作流，增加逐文件 SHA-256 资源校验；AGENTS.md 和部署规则明确要求实际浏览器显示及交互验收。

## 后续规则

以后发布必须使用 `.github/workflows/linux-build.yml` 生成 Linux artifact；ECS 只解压候选包、验收、切换软链接和重启服务，不在服务器执行 `npm ci` 或 `npm run build`。详见 `docs/部署/轻量部署规则.md`。
