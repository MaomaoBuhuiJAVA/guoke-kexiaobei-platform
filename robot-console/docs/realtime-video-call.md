# 科小贝实时视频通话接入说明

生产状态：2026-11-16 已部署至 https://guokeey.cn ，当前发布提交 `0016c68718e639dd8a4ad2e62633045bb7db6fad`。完整验收范围及回滚见 `docs/releases/2026-11-16-实时视频通话上线.md`。下文保留开发阶段检查记录，当前线上状态以该发布记录及实时检查为准。

## 开通与配置

1. 打开阿里云百炼北京地域控制台。**华北 2 就是北京，对应 `cn-beijing`，无需更换地域。**
2. 在模型广场“更多筛选”中选择 **Realtime**。本次已在账号页面确认存在 `Qwen3.8-Omni-Flash-Realtime`，模型 ID 为 `qwen3.8-omni-flash-realtime`。只选“全模态”时，不一定显示实时版卡片。
3. 在百炼管理区域找到当前业务空间 ID，并准备该地域、该业务空间下的百炼 API Key。模型在列表出现不代表已完成实际调用验收；调用权限、账号服务状态和费用以控制台为准。
4. 将以下配置加入当前工作区 `robot-console/.env.local`，重启本地服务。密钥只在环境文件中填写，不粘贴到聊天、源码或发布记录。

```dotenv
QWEN_REALTIME_API_KEY="在本机填写百炼密钥"
QWEN_REALTIME_WORKSPACE_ID="在本机填写业务空间ID"
QWEN_REALTIME_REGION="cn-beijing"
QWEN_REALTIME_MODEL="qwen3.8-omni-flash-realtime"
QWEN_REALTIME_VOICE="Tina"
```

已存在官方 `DASHSCOPE_API_KEY` 时可作为实时密钥的备用来源；业务空间也可使用 `DASHSCOPE_WORKSPACE_ID`。现有 `QWEN_TTS_API_KEY` 不自动用于实时服务，因为原文字、视觉和语音接口可能使用不同网关。实时接入只连接北京或新加坡的官方百炼域名。

官方文档：https://help.aliyun.com/zh/model-studio/realtime

## 实现与数据流

- `src/components/SciencePet.tsx` 增加视频入口；只在打开时动态加载面板。
- `VideoCallPanel.tsx` 使用页面根层 Portal 显示，隔离原宠物浮层的指针事件与堆叠规则。先检查配置，再由用户点击启动摄像头和麦克风。
- `src/lib/realtime-video-call.ts` 管理会话。浏览器采集真实音视频，WebRTC 轨道持续发送给实时模型。收到会话配置确认后才启用输入轨道。
- `POST /api/video-call/session` 在后端通过百炼密钥交换 SDP，返回连接应答和不含密钥的会话配置。GET 仅表示本机配置是否齐全，不证明上游权限可用。
- 控制器同时兼容本地 DataChannel 和百炼服务端 `txt` 通道，发送一次 `session.update`；处理输入转写、回答字幕、VAD 打断与连接错误。
- 用户插话后，旧回答字幕与迟到的工具结果不能覆盖新一轮。手动打断同时取消当前模型响应并停止旧音频输出。
- 园本查询仅允许固定的只读工具 `search_science_resources`，后端校验名称和参数，复用现有资源检索。资源使用 `/lab?item=` 链接展示在对话记录中。
- 关闭摄像头会停止真实视频轨道；重新开启或切换镜头时重新采集。挂断、页面隐藏、离开页面、卸载和连接失败均停止所有本机轨道与播放器。
- 应用不持久化原始音视频，已完成的文字字幕进入既有本地对话记录。供应商数据处理以百炼实际条款和配置为准。
- 单次本机通话在十分钟后结束，可以重新拨打。该限制用于控制会话长度，不代替供应商的计费与限流。

## 验证情况与限制

- 自动测试覆盖：配置来源与地域限制、SDP 格式/大小/来源、凭证不回显、上游失败；权限迟到释放、网络失败、配置确认、摄像头停止与重新采集、打断与旧字幕隔离、旧工具结果丢弃、晚到的摄像头状态隔离。
- 本次真实浏览器已验证：首页打开科小贝、进入视频面板、未配置状态提示、返回文字、关闭面板和 Escape；桌面与手机尺寸均检查截图，修复了原宠物浮层指针事件继承造成的点击穿透。
- 已从用户提供的百炼导出 CSV 配置本机实时密钥、业务空间和北京地域，密钥仅保存在 Git 忽略的 `.env.local`。WebSocket 鉴权、应用会话配置、文本及语音输出通过；实际应用 SDP 代理返回 200，WebRTC 合成音视频问答通过。
- 合成画面左侧红圆、右侧蓝色正方形，合成语音提问后模型准确回答颜色和形状；输入语音转写成功，RTP 实际发送 66 帧，返回远端音频轨道，响应 completed，无接口错误。纯文字问题搭配静音音轨的试验没有取得画面上下文，正式验收以语音触发的完整轮次为准。
- **尚未用用户真实摄像头或麦克风向百炼完成问答；真人插话、音色听感、真实物品、真实终端与弱网延迟仍待实机验收。设备检查曾短暂打开本机音视频轨道并立即停止，未向模型发送或保存设备内容。当前配置只在本地工作区，未配置或部署到生产 ECS。**
- 用户实际点击后发现控制器保存原生 `fetch` 再以实例方法调用，造成浏览器 `Illegal invocation`；已绑定原生浏览器接收者并添加回归测试。此前独立探针没有覆盖实际控制器，现已用真实控制器两次完成合成音视频识别、字幕与恢复聆听，均准确识别红圆和蓝方块。设备检查同时确认本机音视频轨道可以打开并立即释放。
- 本地首页读取数据库时使用既有静态回退；本次未连接生产数据库。浏览器无相关脚本错误，原页面在路由切换时有 Next.js 平滑滚动属性提示。
- Android、iOS Safari、微信内浏览器和弱网需真机验收，不能仅根据 Chromium 尺寸模拟宣称兼容。

## 上线前操作

1. 先配置百炼并进行真实物品问答、换物体追问、语音插话、镜头切换、静音、后台、断网和挂断验收。
2. 生产配置只写到 ECS 既有运行环境中，密钥不提交 GitHub。
3. 按仓库 `AGENTS.md` 使用 GitHub Actions Ubuntu/Node.js 22 构建生产包；执行 `scripts/verify-standalone-package.mjs`，校验成功再发布。ECS 不运行依赖安装和生产构建。
4. 生产验收包含 HTML、引用的 CSS/JS/图片、实际样式和至少一项交互；失败回滚。未经真实通话验收，不将本功能描述为已上线可用。
